# MVP要件定義書：AI生徒育成型・対話学習サービス

## 1. プロダクト概要

* **コンセプト**: 「ユーザーが先生、AIが生徒」。他人に教えることで自分自身の理解が最も深まる学習効果（プロテジェ効果）を最大化する、育成・対話型の学習サービス。
* **ターゲット**: 中学生・高校生（MVPではホワイトボードを使った図解と口頭説明の相性が良い「数学」「理科」の2教科を中心に検証し、将来的に5教科へ拡張可能な構成とする）。
* **利用環境**: タブレット端末（横向き表示推奨）＋スタイラスペン＋マイク入力。

## 2. ユーザーロールとキャラクター定義

### 2.1 ユーザー

* **先生（プレイヤー）**: 自身の学習教材を持ち込み、予習を行った上でAI生徒に授業を行う。

### 2.2 AIキャラクターと内部機能（3つの役割）

1. **先輩先生（先生準備室）**
   * **役割**: ユーザーが教材の分からない箇所を質問し、教え方のアドバイスをもらえる頼れるメンター。
   * **対話スタイル**: 画面上のキャラクターが豊かな表情や身振りを交えながら自然な音声で対話し、共有ホワイトボード上に図やポイントを書き込みながら解説してくれる。

2. **AI生徒（授業・模試）**
   * **役割**: ユーザーから授業を受ける生徒。初期MVPでは個性や学力レベルの異なる以下3タイプから1人を選択可能とする。
     * **タイプA（直感・感覚派 / 偏差値45）**: 難しい専門用語に弱く、図解や身近な具体例を求める。
     * **タイプB（真面目な暗記派 / 偏差値52）**: 公式は覚えているが「なぜその解き方を使うのか」という発想のプロセスを質問してくる。
     * **タイプC（論理・ツッコミ派 / 偏差値60）**: 説明の飛躍や例外ケースについて鋭く質問してくる。
   * **対話スタイル**: 画面上のキャラクターが感情豊かな表情と声でリアクションし、ホワイトボード上の分からない箇所を指し示したり「？」マークを書き込んだりしながら質問してくる。

3. **学習評価機能（裏側の仕組み）**
   * **役割**: 持ち込まれた教材から「この問題で教えるべき重要ポイント」を整理し、授業中のユーザーの説明がそれを満たしているかを判定してAI生徒の理解度に反映する。

## 3. 画面構成とユーザーフロー（MVPスコープ）

```
[1. 初期セットアップ（担当生徒の選択・週間シフト設定）]
       ↓
[2. ホーム画面（生徒の様子・スケジュール確認）]
       ↓
[3. 先生準備室（教材の持ち込み・先輩先生への質問と予習）]
       ↓
[4. 授業画面（ホワイトボード共有 ＋ 音声での解説 ＋ まとめノート作成）]
       ↓
[5. 模試・結果発表画面（理解度に応じたテスト結果・成長記録のシェア）]
```

## 4. 機能要件（Functional Requirements）

### 4.1 初期セットアップ・継続管理機能

* **FR-101 担当生徒の選択**: 見た目、性格、初期偏差値、目標レベルが設定された3名の生徒から、担当する生徒を1人選択できる。
* **FR-102 担当教科・単元設定**: 今回の指導対象となる教科・単元を選択できる。
* **FR-103 週間シフト設定**: 週に何回（または何曜日に）授業を行うかの目標シフトを登録できる。
* **FR-104 休講・自習モード（離脱防止）**: ユーザーが忙しい日は、ワンタップで「自習指示」または「宿題の丸つけのみ（短時間の添削）」に切り替えられ、シフト未達成の罪悪感による利用離脱を防ぐ。

### 4.2 先生準備室機能（インプット＆教材セット）

* **FR-201 教材の持ち込み**: ユーザーが自分の問題集やプリントの写真（またはファイル）を登録できる。
* **FR-202 問題の清書と指導ポイントの整理**: 登録された教材から、以下の情報が自動的に整理・準備される。
  1. ホワイトボード上で扱いやすく清書された問題文と図表
  2. 模範解答と解説のステップ
  3. **指導のポイント（この問題でAI生徒に伝えるべき重要ポイント3点）**
  4. **AI生徒の初期つまずき状態（途中まで解いて手が止まっているノート状態）**
* **FR-203 先輩先生への質問・予習**: 整理された問題をもとに、授業本番と同じ操作感（ホワイトボードを共有しながらの音声対話）で、分からない箇所や教え方のコツを先輩先生に質問できる。

### 4.3 授業機能（コア体験：アウトプット）

* **FR-301 ホワイトボードの初期配置**: 授業開始時、ホワイトボード上に「問題エリア」と「AI生徒が途中まで書いて悩んでいる解答エリア」が配置された状態でスタートする。
* **FR-302 描画と連携した自然な音声対話**:
  * ユーザーはペンでホワイトボードに式や図を書きながら、口頭でAI生徒に解説を行える。
  * **書いている最中の割り込み防止**: ユーザーがホワイトボードにペンで書いている最中や、書き終えた直後の思考中は、無言であってもAI生徒が勝手に話し出さず、ボードを見ながら頷いて待つ。
  * **指し示し（ポインター）の認識**: ユーザーが「ここ」「この式」と言いながらボード上を指し示したり線を引いたりした際、AI生徒はどの部分を指しているかを正確に理解して応答する。
* **FR-303 AI生徒のリアクションと質問**:
  * AI生徒は最初から答えを知っている状態ではなく、ユーザーの言葉とホワイトボードの記述内容だけを手がかりに理解しようとする。
  * 説明に飛躍や不足がある場合は、困った表情や声色でホワイトボード上の該当箇所を指し示しながら、「なぜこうなるのですか？」と質問を返す。納得した際は表情が明るくなり、理解度の上昇が演出される。
* **FR-304 チャイム制（授業時間の区切り）**: 1回の授業は学校の休み時間感覚で取り組めるよう、開始から10分、またはユーザーとAI生徒のやり取り20往復のいずれか早い方でチャイムが鳴り、まとめフェーズへ移行する。
* **FR-305 まとめノートの作成**: 授業の最後に、AI生徒が今日教わった内容を整理した「まとめノート」をホワイトボード上に作成して見せてくれる（ユーザーが授業中に描いた分かりやすい図や式もノート内に引用される）。

### 4.4 模試・評価・シェア機能（ゲーミフィケーション）

* **FR-401 理解度の蓄積**: 授業中に「指導のポイント」をどれだけ分かりやすく伝えられたかに応じて、単元ごとのAI生徒の理解度が蓄積・更新される。
* **FR-402 模試イベント**: 授業を重ねた後、AI生徒が「模試（教えた問題の類題や応用問題）」に挑戦するイベントが発生する。
* **FR-403 模試結果・解答用紙の表示**: 蓄積された理解度に基づき、AI生徒が実際に書いた解答用紙、得点、偏差値の推移、および生徒からのコメント（「先生が教えてくれた〇〇は解けたけど、△△は迷ってしまいました」など）を表示する。
* **FR-404 成長記録と学習レポートのシェア**: AI生徒が作った「まとめノート」や「模試結果」、および「ユーザー自身が指導を通じて定着させた学習単元のレポート（本人や保護者の振り返り用）」を画像として保存・シェアできる。

### 4.5 継続と振り返りの機能をMVPに含める理由

FR-103・FR-104（週間シフトと休講・自習モード）とFR-404（学習レポートのシェア）は、授業のコア体験そのものではないが、次の理由でMVPの検証対象に含める。

* プロテジェ効果は1回の授業では測れず、教える行為を継続できるかどうかが検証の前提になる。シフトの未達成による罪悪感からの離脱は、継続を妨げる要因として先に確かめたい（FR-103、FR-104）
* 指導を通じて自分に何が定着したかを本人と保護者が振り返れることは、中学生・高校生が使い続ける動機として検証対象に含める（FR-404）

いずれも授業のコア体験（4.3）が動かなければ検証できないため、実装の優先順位はコア体験の後とする。

## 5. 非機能要件・体験品質の基準（Non-Functional Requirements）

### 5.1 対話の自然さとテンポ

* **NFR-101 待ち時間を感じさせないリアクション**: ユーザーが話し終えてからキャラクターが反応するまでの間に不自然な沈黙が生まれないよう、話し終えた直後に「頷く」「顎に手を当てて考える」といった仕草や、「えーっと…」「なるほど！」といった自然な相槌を即座に挟み、対話のテンポを損なわないこと。

### 5.2 利用時間・運営コストの適正化

* **NFR-201 1授業あたりの時間・回数上限**: ユーザーの集中力を維持し、かつサービス運営上の通信・処理負荷を適正な範囲に収めるため、1回の授業および準備室での相談には明確な時間制限（チャイム制）とやり取りの回数上限を設けること。上限は、授業が10分またはユーザーとAI生徒のやり取り20往復、準備室での相談が10分または先輩先生とのやり取り15往復とし、いずれか早い方に達した時点で区切る。

### 5.3 データの取り扱い

中高生が教材の画像や音声を持ち込み、学習の記録を画像で共有するため、MVPに必要な範囲で次のとおりとする。

* **NFR-301 外部AIサービスへの送信**: 教材の画像、宿題の写真、ホワイトボードの記述、音声、字幕は、問題の清書・対話・音声認識・音声合成のために外部のAIサービスへ送信する。送信するのは、その処理に必要なデータだけとする。
  * アプリは氏名・学校名・連絡先を入力させず、これらを項目として保持・送信しない。
  * ユーザーが話した内容、書いた内容、写した写真の中身は、アプリが個人情報の検出や除去を行わずに送信する。そのため、氏名・学校名・連絡先を話さない・書かない・写さないことをユーザー自身が確認する方式とし、初期セットアップと、写真を送る操作の前に確認を求める。授業と相談の画面にも同じ注意を表示する。
* **NFR-302 保存するデータ**: 教材、まとめノート、模試結果、理解度はアカウントに紐づけて保存する。音声の録音データは、対話の処理に使った後は保存しない。
* **NFR-303 削除**: ユーザーは、登録した教材と学習の記録を自分で削除できる。
* **NFR-304 共有の範囲**: シェアは画像の書き出しに限り、URLでの公開や、ほかのユーザーからの閲覧は行わない。

## 6. MVPにおける「作らないもの（スコープ外）」

初期検証を素早く行うため、以下の要素はMVPでは対象外とする。

1. **自由なキャラクターメイキング機能**: 見た目や性格をゼロから細かくカスタマイズする機能は作らず、魅力的な既存の生徒キャラクターから選ぶ方式に絞る。
2. **勉強以外のフリートーク機能**: 学習内容に関係のない無制限の雑談モードは設けない。
3. **ユーザー間の対戦・交流機能**: 他のユーザーの生徒とリアルタイムで競うような複雑な通信機能は作らず、結果画像のシェア機能のみとする。
4. **専用アプリのストア配信**: 初期はタブレットの標準ブラウザからすぐに利用できるWebサービスとして提供する。

## 7. 受け入れ基準（Acceptance Criteria）

MVPとしてサービスが成立していることを確認するためのチェック項目。

* [ ] **AC-1**: ユーザーが教材の画像を登録すると、問題と「教えるべき重要ポイント」が整理され、ホワイトボードと音声を使って先輩先生に質問・予習ができること。
* [ ] **AC-2**: 授業中、ユーザーがホワイトボードにペンで書いている最中は、無言になってもAI生徒が話を遮らずに待ってくれること。
* [ ] **AC-3**: ユーザーの口頭説明とホワイトボードの記述内容に応じて、AI生徒が表情や声色を変えながら自然な質問や相槌を返し、生徒の理解度が内部で変化すること。
* [ ] **AC-4**: 授業の終わりに、教えた内容やユーザーの板書を反映したAI生徒の「まとめノート」が提示されること。
* [ ] **AC-5**: 授業での指導内容に応じた「模試結果（得点・解答内容・生徒のコメント）」が画面に表示されること。
* [ ] **AC-6**: 授業の開始から10分、またはユーザーとAI生徒のやり取り20往復のいずれか早い方に達した際、チャイムが鳴って自然に授業のまとめへ移行すること。
* [ ] **AC-7**: 初期セットアップで担当する生徒と教科・単元を選び、週間シフトを登録できること。また、忙しい日はワンタップで自習指示または宿題の丸つけに切り替えられること。
* [ ] **AC-8**: AI生徒が作ったまとめノートと模試結果、およびユーザー自身が指導を通じて定着させた学習単元のレポートを、画像として保存・シェアできること。

### 7.1 自動の受け入れテストで確かめる範囲

受け入れテストはPlaywrightで書くため、ホワイトボードへのペン入力、音声の入出力、キャラクターの表情・声色・音声の自然さは確かめられない。自動の受け入れテストで確かめるのは、`docs/project.md` の方針に合わせ、画面遷移と、画面に表示される内容と、ユーザーとAI生徒の対話が往復として成立することまでとする。AI生徒の理解度のような、画面に表示されない内部の状態そのものは、自動の受け入れテストでは確かめない。

次の項目は、自動の受け入れテストでは確かめず、人が実際に触って判断する。

* **AC-2**（ペンで書いている最中にAI生徒が待つこと）
* **AC-3**（表情・声色の変化、質問や相槌の自然さ、および理解度が内部で変化すること）
* **AC-1のうち、音声での対話そのもの**（教材の登録と重要ポイントの整理は、自動の受け入れテストで確かめる）
* **NFR-101**（相槌や仕草による対話のテンポ）
