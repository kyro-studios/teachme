# プロジェクトの背景

## 目的と背景

### 背景

現代の日本の教育はパッシブ（受け身）な学習が中心である。
一方で、自身が教わるよりも、自身が教えるほうが学習効果が高まることが知られている。
また、誰かに教えるという行為に対し、社会的責任を覚え、結果モチベーションが高まるという研究結果も報告されている。
しかし、従来の学習環境や生徒自身の環境において、誰かに教えるという体験の場は設けられていないのが現実である。

### 目的

中学生・高校生を主な対象とした、「ユーザーが先生となり、AIの生徒に勉強を教える」ことで学習定着（プロテジェ効果）を促す対話型 Web アプリケーション。
タブレット端末とスタイラスペンでの利用を前提とし、本サービスでの学習を通じてユーザーの主体的なインプットとアウトプットを支援する。

## 規模

- **想定する利用者の数**: MVP検証フェーズとして数十人〜100人規模（初期は対象を特定の教科・単元に絞って検証）
- **見積もりの総コスト**: CodexのAPI利用料10$未満。Claudeはサブスクの枠内で動かすため、API利用料はかからない（対話で使うClaude Codeと枠を共有するため、枠の消費は抑えること）
- **総工数**: 未定
- **期限**: 2026/10/30 23:59まで

## 方針

- **優先順位**: D (納期) > C (費用) > Q (品質)
- **品質の水準**: MVP（実用最小限の製品）
  - コア体験の正常系フローが動くことを最優先とする。
  - 受け入れテストでは、主要なユーザーフローの正常系と、APIの無限ループ（トークン・音声生成コストの暴走）や進行不能になる致命的な異常系のみを確かめる。エッジケースの網羅や過剰なパフォーマンス最適化、複雑な権限管理などは行わない。

## そのほかの制約

- **デバイス・UI制約**: タブレット画面（横向き）＋ペン入力での操作性を最優先としたレスポンシブ設計とすること。
- **必須技術・外部サービス**:
  - ホワイトボード機能には `tldraw` を使用すること。
  - AI生徒の描画・アニメーションには `Live2D` を使用すること。
  - AI生徒の音声合成には `ElevenLabs v4`を使用し、自然なコミュニケーションを実現すること。
- **対話・APIコストの制約**:
  - 外部AIサービス（マルチモーダルLLM、STT、ElevenLabs）の従量課金コストは肥大化しないよう気を付けること。
- **受け入れテストの制約**:
  - テストを実行する環境には、Secretsもジョブの環境変数も渡らない。そのため、テスト中のアプリケーションから外部AIサービス（マルチモーダルLLM、STT、ElevenLabs）のAPIキーは読めない。これらをスタブやフェイクに差し替えて起動できる構成とすること。
  - 受け入れテストで確かめるのは、画面遷移と、ユーザーとAI生徒の対話が往復として成立することまでとする。手書きのストロークそのもの、音声入力、Live2Dの描画や音声の自然さは、受け入れテストでは確かめず、人が見て判断する。
